# AGENTS.md — контекст проекта для omp

Этот файл читается агентом (omp) автоматически при запуске в этой папке. Здесь всё, что нужно,
чтобы продолжить работу **без доступа к прошлой переписке**: что за проект, где что лежит,
как выпускать версии, как проверять и где мы остановились.

Если ты агент и только что открыл проект — прочитай этот файл целиком, затем `docs/*.md`.

---

## Что это за проект

**Русская локализация интерфейса Orca** — плагин-языковой пакет для Orca (ADE для оркестрации
AI-агентов). Плагин не исполняет код: это один файл перевода `locales/ru.json`, который Orca
подхватывает через `contributes.languagePacks`.

- Плагин id: `russian`, publisher: `taranttoola-create`, ключ: `taranttoola-create.russian`
- Текущая версия: **1.3.4** (см. `orca-plugin.json`)
- Записей в каталоге: **14 861** (`locales/ru.json`, ~1,3 МБ)
- Целевая версия Orca: **1.4.219** (совместимость заявлена от 1.4.169)

## Как запустить / проверить

```bash
# Открыть проект в Orca и запустить в нём omp:
#   Settings → Plugins открыт не нужен; просто создать worktree/панель на этой папке
#   и выполнить в терминале:
omp                       # интерактивно, читает этот AGENTS.md

# Проверить, что каталог валиден (нужен распакованный asar — см. tools/README.md):
node tools/validate-catalog.mjs

# Проверить и выпустить новую версию — см. docs/WORKFLOW.md
```

## Ключевые правила проекта (не нарушать)

1. **Плейсхолдеры не трогать.** `{{value0}}`, `{{count}}`, `{{name}}` сохранять буквально.
2. **Продукты не переводить:** Orca, GitHub, Codex, Claude, Gemini, ZCode, MCP, macOS и т.п.
3. **Защищённые пути** `auto.components.settings.Plugin*` — НЕ добавлять в каталог.
   Исключение: 34 разрешённых «chrome»-пути (они уже переведены).
4. **Значения длиннее 8192 символов запрещены** — валидатор отклонит весь каталог. Это две
   CSS-строки (`...visual.notes.styles.*`, `...visual.ship.styles.*`) — не переводим.
5. **Лимит каталога 20 000 записей** (сейчас 16 712 с учётом вложенности).
6. **id плагина не менять** и не начинать с `orca-` (префикс зарезервирован за stablyai).
7. Глоссарий: worktree→worktree, workspace→рабочая область, agent→агент, session→сессия,
   terminal→терминал, chat→чат, plugin→плагин, marketplace→маркетплейс.

## Как обновлять перевод при выходе новой Orca

Полный процесс — в `docs/WORKFLOW.md`. Кратко: скачать `en.json` из тега Orca →
сравнить с `locales/ru.json` → перевести недостающее → удалить устаревшее → проверить
валидатором → выпустить новую версию.

## Где мы остановились (важно!)

**Текущее состояние:** v1.3.4 выпущена и запушена в оба зеркала. Работа по переводу
синхронизирована с Orca 1.4.219 — непереведённых строк в каталоге нет.

**Установка в Orca — отдельный шаг, вручную.** Orca не обновляет плагин, поставленный по
git-ссылке: в `~/Library/Application Support/Orca/plugins/taranttoola-create.russian/`
лежит та версия, которую поставили руками, и `current` указывает на неё. Чтобы интерфейс
подхватил свежий перевод, нужно переустановить пак: Settings → Plugins → Install plugin →
Git URL → ссылка с новым тегом (актуальная ссылка — в `README.md`). На момент записи в Orca
стоит контент v1.3.3 — после переустановки эту строку обновить.

**Открытые вопросы (важно, не потерять):**

1. **Названия сочетаний клавиш не переводятся.** Они захардкожены в самом приложении
   (`src/shared/keybindings/definitions-core-*.ts`), рендерятся без `translate()`. Мы
   отправили готовый патч — **issue stablyai/orca#25048**. Мы заранее положили в пак 139
   ключей `keybinding.*` (v1.3.3). **Если патч примут с нашей схемой — переводы включатся
   сами.** Если схему изменят — ключи придётся переименовать. Детали: `docs/UPSTREAM.md`.
2. **Разработчики Orca почти не отвечают в GitHub.** 7 432 открытых issue, 0 из 11
   community-PR в маркетплейс смержено. Живой канал — **Discord: https://discord.gg/fzjDKHxv8Q**
   (~5.4к участников, создан мейнтейнером nwparker). Туда стоит написать, если нужен ответ.
3. **PR в официальный маркетплейс** — `stablyai/orca-plugins#9`, обновлён на v1.3.4, ждёт
   ревью (без шансов на скорое, см. п.2). **Обход очереди уже сделан:** в корне репозитория
   лежит `orca-marketplace.json` — свой источник маркетплейса (Settings → Plugins →
   Manage sources → Add source), проверенный схемой Orca 1.4.219. Механика — в
   `docs/KNOWLEDGE.md`, раздел «Свой источник маркетплейса».
4. **Плюрали.** Русскому нужно 4 формы, Orca умеет 2 (`_one`/`_other`). Наши 19 семейств
   заполнены корректно, но при 2–4 покажет форму `_other`. Чинится только в Orca (PR #12505).

Всё это расписано подробнее в `docs/`.

## Полезные факты об окружении

- macOS, приложение Orca в `/Applications/Orca.app`, обновляется автоматически
  (`brew` предлагает устаревшую версию — игнорировать, приложение самообновляется).
- omp v18.0.11, установлен в `/usr/local/bin/omp`. Orca настроена использовать omp
  как агента по умолчанию (`defaultTuiAgent = "omp"`).
- Codex в Orca идёт через Cockpit-прокси (`~/.antigravity_cockpit`), модели с api.buheirf.ru.
  На OpenAI-аккаунтах периодически кончаются кредиты — это к делу не относится, но объясняет
  ошибки 429 в чатах агентов.
- Проверка каталога требует распакованного `app.asar` (Node-модуль валидатора Orca) —
  `tools/validate-catalog.mjs` умеет распаковать сам.
