# TRANSLATION.md — процесс перевода

Как переводить строки и как устроена механика батчей/агентов. Дополняет `WORKFLOW.md`.

## Правила перевода (жёсткие)

1. **Ключи не менять.** Переводим только значения.
2. **Плейсхолдеры сохранять буквально:** `{{value0}}`, `{{value1}}`, `{{count}}`, `{{name}}`.
   Порядок слов можно менять, но сами токены — нет.
3. **Плюральные суффиксы:** `_one` (1), `_other` (всё остальное). Суффиксы `_few`/`_many`
   в каталог **не добавлять** — Orca их не читает.
4. **Не переводить:**
   - продукты и бренды: Orca, GitHub, GitLab, Codex, Claude, Gemini, GLM, ZCode, Z.ai,
     Cursor, Qoder, CodeBuddy, DeepSeek, MCP, macOS, Windows, VS Code, Monaco, zellij,
     warp, yaml, wsl, vm, omp, OMP;
   - URL, пути, команды (`/clear`, `/compact`), сочетания клавиш (⌘, ⌥, ⇧, Ctrl+K),
     идентификаторы;
   - строки чистого CSS/HTML (некоторые такие есть в en.json — их вообще не включать).
5. **Стиль:** краткий UI-русский, инфинитивы для действий («Проверить обновления»),
   императив для кнопок («Отмена», «Повторить», «Готово»). Точка в конце — только если
   она есть в английском оригинале. Сохранять `…` и `—`.
6. **Глоссарий** (см. `CONTRIBUTING.md`): worktree→worktree, workspace→рабочая область,
   agent→агент, session→сессия, snapshot→снимок, plugin→плагин, marketplace→маркетплейс,
   commit→коммит, diff→дифф, branch→ветка, repo→репозиторий, terminal→терминал, chat→чат,
   subagent→субагент.

## Механика: батчи

При больших обновлениях (сотни строк) переводят **батчами**:

1. Из diff'а берутся только реально переводимые ключи (защищённые и oversize — вон).
2. Делятся на батчи по ~120 строк → JSON-файлы `{ключ: английский текст}`.
3. Каждый батч переводится отдельным проходом с одинаковым промптом (правила выше).
4. Батчи сливаются, проверяются плейсхолдеры и совпадение множеств ключей.

**Важно:** не запускать много переводящих агентов параллельно — упирается в лимиты API
(был случай с ошибками про `reasoning_text`). Надёжнее последовательно.

## Проверки после перевода

```bash
node tools/validate-catalog.mjs
```

Проверяет:
- JSON валиден;
- нет значений > 8192;
- нет защищённых `Plugin*` путей (кроме 34 разрешённых);
- лимиты записей/глубины;
- **дрейф плейсхолдеров** — для каждого ключа сверяет набор `{{...}}` с `en.json`;
- покрытие: чего ещё нет.

Плейсхолдеры — самая коварная часть: Орка не падает на строке с потерянной подстановкой,
она просто отображается криво. Такое уже проскакивало в релиз (см. `CONTEXT.md`).

## Как переводятся «недостижимые» строки

Часть интерфейса вообще не проходит через каталог (хардкод, `translate()` не вызывается).
Такие строки **паком не перевести**. Что делаем:

- документируем и отправляем в апстрим (issue #17913, #25048);
- для известного будущего фикса заранее готовим ключи (пример: 139 ключей `keybinding.*`
  в v1.3.3 — ждут, пока Orca начнёт читать их).

## Экспорт недостающего (пример)

```bash
# diff: что есть в en.json, но нет в нашем ru.json, кроме защищённого и oversize
node tools/sync-with-orca.mjs /tmp/en-orca.json --export /tmp/missing.json
```

Далее `/tmp/missing.json` делится на батчи и переводится.
